# Module 4 evaluation methodology

Backtest uses the Module 1 chronological held-out test dates 2025-09-13 through 2025-12-31 (110 days, 50 products). All policies use the same realized demand for each product/date, source cost parameters, initial inventory, and common random-number supplier lead-time realizations (seed 404). Contextual forecasts use 25 scenarios per window (scenario seed base 704). Test outcomes are used only for simulation and reporting, never for orders at that date.

Policies make one order decision at the start of each rolling 30-day review window. This preserves Module 3's one-order-per-horizon distinction; it is not a daily reorder policy. Context and non-context policies are re-optimized at each window start from forecasts generated using only demand history through the prior day. Module 2 model artifacts are held fixed (trained on the earlier training split). The conventional baseline orders up to trailing-28-day mean demand times review horizon plus average lead time, capped at the dataset per-product capacity.

Supplier lead time is sampled as ceil(max(0, average + standard deviation * Normal(0,1))). A common Bernoulli reliability outcome is applied per product/window; a failed first attempt adds one ceil(average lead) retry cycle, after which delivery is assumed successful. This explicit simplification is simulation only; Module 3 still optimizes deterministic average lead. Sensitivity cases freeze base order decisions while increasing lead-time standard deviation by 1.5x or holding/shortage cost coefficients by 1.5x.

Module 2 scenario IDs are coherent recursive paths over the forecast horizon within each product because sampled demand updates that scenario's lag history. Product draws are conditionally independent; no cross-product shock or dependence is represented. Those forecasts are used only to make orders; the primary backtest scores realized held-out demand, not generated scenarios.

Fill rate is total fulfilled units divided by total realized demand. Stockout product-days count product-date pairs with positive lost sales; stockout frequency divides by product count times evaluation dates. Average on-hand inventory is the mean ending stock over all product-days; average inventory value is mean daily total ending stock times unit cost. Purchase and fixed order costs are charged when an order is placed, even if delivery falls after the test end. Such pipeline units are reported separately. Costs use source holding cost and selling price as the lost-sales penalty.

Limitations: results are for one synthetic historical holdout and one fixed random lead-time realization per product/window; they are not universal evidence. No outstanding shipment crossed a review-window boundary or remained at the test end in this run. The optimizer receives no pipeline state at window boundaries, so a different lead-time setup with cross-window arrivals needs an explicit pipeline state. Supplier reliability is represented by one delayed retry only. Future promotion/festival covariates in Module 2 forecasts default to zero. Sensitivity replays do not re-optimize decisions. Reported computation time for the conventional rule is 0 solver seconds because it does not call an optimizer; it is not a wall-clock benchmark of the simulator.
